CHAPTER 6

第6章 纹理 (Texturing)

"实时渲染中最强大的工具之一，就是能够快速访问图像，并将其显示在表面上。这个过程叫做纹理化，有各种各样来实现它的方法。"

-- RTR4, Chapter 6

这段话告诉我们：纹理化（Texturing）是实时渲染赋予物体表面丰富视觉细节的核心手段。没有纹理，3D 场景中的物体就像是没有花纹的白色纸盒——虽然几何形状正确，但缺乏真实感。纹理让我们能够用一张 2D 图像来控制 3D 表面的颜色、粗糙度、法线方向等各种属性。

通俗比喻：纹理就像给 3D 模型"穿衣服"。
想象一个白色的石膏雕塑（几何体），你可以给它贴上一层木纹的"皮肤"让它看起来像木头，贴上一层砖纹让它看起来像砖墙，甚至贴上一层"凹凸"的图案让光滑的表面看起来有纹理感。纹理就是控制"贴什么图案"以及"怎么贴"的技术。

6.1 纹理映射原理 (Texture Mapping Basics)

纹理映射的核心思想是：为网格（Mesh）的每个顶点指定一组 UV 坐标，然后在片元着色器中对 UV 坐标进行插值，最后用插值后的 UV 从纹理图像中采样颜色。

UV 坐标详解：UV 是一个二维坐标 (u, v)，通常范围在 [0, 1] 之间。可以把它理解为"纹理图片上的百分比位置"——u = 0.5 表示水平方向的中点，v = 0.25 表示垂直方向的 1/4 处。每个三角形的三个顶点各有自己的 UV 坐标，三角形内部的像素通过重心坐标插值获得自己的 UV 值。

纹理映射的完整管线如下：

  1. UV 展开（UV Unwrapping）：在建模软件中，将 3D 模型表面"展开"到 2D 平面上，为每个顶点分配 UV 坐标
  2. 纹理上传：将纹理图像数据传输到 GPU 的专用纹理内存中
  3. 顶点着色阶段：将顶点的 UV 坐标传递给光栅化器
  4. 光栅化插值：在三角形内部对 UV 坐标进行透视校正插值（perspective-correct interpolation）
  5. 片元着色采样：用插值后的 UV 从纹理中读取颜色值
  6. 纹理过滤：当 UV 采样的位置不完全对齐纹理像素（texel）时，决定如何计算最终颜色
💡 透视校正插值
在光栅化阶段，UV 坐标不能简单地线性插值——否则远处物体的纹理会看起来"游动"。GPU 使用透视校正插值，对 UV 除以 w（深度分量）后插值，再乘回来，确保纹理在 3D 透视中正确显示。

6.2 纹理过滤 (Texture Filtering)

纹理过滤解决的核心问题是：当 UV 坐标对应的纹理位置不恰好落在纹理像素（texel）中心时，应该取哪个颜色？更关键的是，当屏幕上的一个像素覆盖了多个 texel（minification，缩小）或一个 texel 覆盖了多个屏幕像素（magnification，放大）时，如何计算正确的颜色。

常见的纹理过滤方式有三种：

过滤方式英文名称原理视觉效果
最近邻 Nearest / Point 直接取最近的 texel 值 像素化/马赛克感
双线性 Bilinear 取最近的 2x2=4 个 texel，按距离加权平均 较平滑，远处仍有闪烁
三线性 Trilinear 在两个 Mipmap 层级上各做双线性插值，再在层级间线性插值 最平滑，消除层级切换缝隙
双线性插值公式： color = lerp(lerp(c00, c10, u_frac), lerp(c01, c11, u_frac), v_frac) 其中 c00, c10, c01, c11 是最近的 4 个 texel 颜色，u_frac 和 v_frac 是小数部分
实践建议：在大多数游戏和应用中，三线性过滤是默认且推荐的选择。它只比双线性多一次插值计算，但显著改善了远处纹理的过渡质量。最近邻过滤主要用于像素艺术风格游戏，以保留清晰的像素边界。

6.3 Mipmapping

Mipmap（"mip"来自拉丁语 multum in parvo，意为"小中见大"）是一组预先生成的、分辨率逐级减半的纹理图像序列。一张 256x256 的纹理，其 Mipmap 链为：256x256、128x128、64x64、32x32、16x16、8x8、4x4、2x2、1x1。

金字塔比喻：想象你有一张大尺寸海报和一整套从大到小的缩略图。当你在近处看时用大尺寸的，当走远了就换用小尺寸的缩略图。Mipmap 就是这个"缩略图集合"——GPU 自动选择最合适的层级来采样。

为什么 Mipmap 如此重要？有三个核心原因：

  1. 消除摩尔纹（Moire Pattern）和闪烁：远处的纹理缩小后，高频细节会导致采样不足，产生令人不适的波纹闪烁。Mipmap 预先过滤了这些高频信息。
  2. 提高缓存命中率：采样较小尺寸的 Mipmap 层级时，纹理数据在缓存中更紧凑，减少了显存带宽消耗。
  3. 三线性过滤的基础：没有 Mipmap，就无法在层级间做插值，也就没有三线性过滤。
内存开销：Mipmap 链的总大小约为原始纹理的 1/3（1 + 1/4 + 1/16 + ... = 4/3）。这个 33% 的额外开销换来的是巨大的视觉和性能提升，几乎是"免费的午餐"。

6.4 纹理环绕模式 (Wrapping Modes)

当 UV 坐标超出 [0, 1] 范围时，GPU 需要知道如何处理。这就是环绕模式（Wrap Mode）的作用：

环绕模式英文名称行为描述典型用途
重复 Repeat / Tile UV 的小数部分作为纹理坐标，产生平铺效果 地板、墙壁的重复贴图
钳制 Clamp to Edge 超出范围的 UV 被限制到 0 或 1，纹理边缘被拉伸 天空盒边缘、避免接缝
镜像 Mirrored Repeat 每隔一个周期翻转纹理，避免可见的重复痕迹 水面反射、对称纹理
边框颜色 Clamp to Border 超出范围时返回指定的边框颜色 光照贴图、特殊效果

6.5 多纹理和纹理混合 (Multitexturing)

多纹理（Multitexturing）是指在同一个渲染过程中同时使用多张纹理来决定表面的最终颜色。这在现代渲染管线中极其常见：

  • 漫反射贴图（Albedo Map）：定义表面的基础颜色
  • 粗糙度贴图（Roughness Map）：控制表面的微观粗糙程度
  • 金属度贴图（Metalness Map）：区分金属和非金属区域
  • 法线贴图（Normal Map）：模拟表面的微观凹凸细节
  • 环境光遮蔽贴图（AO Map）：预计算的遮蔽信息

这些纹理在着色器中通过乘法、加法、混合等操作组合在一起，共同决定每个像素的最终外观。

6.6 凹凸贴图 (Bump Mapping)

凹凸贴图（Bump Mapping）是最早用于模拟表面凹凸细节的技术。其核心思想是：使用一张灰度纹理（高度图），通过计算相邻像素的高度差来推导出一个"扰动法线"，然后在光照计算中使用这个扰动法线替代原始几何法线。

贴纸比喻：想象你在光滑的塑料板上贴了一张带有凹凸图案的透明膜。板的形状没有改变（仍然是平的），但从侧面看过去时，图案的凸起部分会遮挡或反射光线，产生"有凹凸"的视觉错觉。凹凸贴图就是用这种"视觉欺骗"的方式在不增加几何复杂度的情况下表现细节。

凹凸贴图的局限性：它只影响光照计算，不会改变表面的实际轮廓。在边缘处（轮廓线/silhouette），你无法看到凹凸效果。

6.7 法线贴图 (Normal Mapping)

法线贴图（Normal Mapping）是凹凸贴图的升级版。它直接存储每个像素的扰动法线方向（以 RGB 编码），而不是存储高度值再推导。法线贴图通常使用切线空间（Tangent Space）编码：

  • R 通道：切线方向的分量（X）
  • G 通道：副切线方向的分量（Y）
  • B 通道：法线方向的分量（Z），通常接近 1.0（蓝色为主）
📚 知识扩展：法线贴图 vs 凹凸贴图

先修正一个常见说法（对照 RTR4 原书）：法线贴图与 Blinn 1978 年的凹凸贴图在数学上等价，差别只在存储格式与像素着色器中的计算操作，不存在原理性的精度差。下面两条是工程实践中的取舍：

  1. 更精确的法线计算：直接存储法线方向，而非通过高度差的差分近似，避免了数值微分的不稳定性。
  2. 可以表示任意方向的法线：凹凸贴图只能沿高度方向偏移，而法线贴图可以表示任意方向的扰动，能够表现更复杂的表面细节。

现代游戏引擎中几乎已经不再使用传统的凹凸贴图，法线贴图是标准做法。在 Unity 中对应的纹理类型为 "Normal Map"，在 Unreal Engine 中需要启用 "sRGB" 关闭（因为法线数据不是颜色数据，不应进行 Gamma 校正）。

CHAPTER 7

第7章 阴影 (Shadows)

"在场景中添加阴影效果可以增强画面的真实感和表现力。我们会在这个章节中介绍几种目前比较流行的、能够快速计算阴影的方法。"

-- RTR4, Chapter 7

阴影是视觉真实感的关键组成部分。人类的大脑非常善于从阴影中推断物体的位置关系、光源方向和表面形状。一个没有阴影的场景，即使光照计算完美，也会让人觉得"假"和"漂浮"。

比喻：阴影是"光的缺席证"。想象你在审问一束光线："你有没有被什么东西挡住？"阴影就是答案——它标记了哪些地方光线"到不了"。有了这个信息，我们就能知道物体之间的空间关系，判断谁在地面上、谁浮在空中。

7.1 阴影映射 (Shadow Mapping)

阴影映射（Shadow Mapping）由 Lance Williams 于 1978 年提出，至今仍是实时渲染中最主流的阴影技术。它的核心思想简单而优雅：

  1. 深度纹理生成：以光源为"相机"渲染一次场景，只记录每个像素的深度值，得到一张阴影贴图（Shadow Map）
  2. 阴影判定：在正常的相机渲染中，对于每个片元，将其坐标变换到光源空间，与阴影贴图中的深度值比较
  3. 在阴影中：如果片元的深度大于阴影贴图中的深度值，说明有物体挡在了它和光源之间，该片元处于阴影中
阴影判定：if (fragDepth > shadowMapDepth) then inShadow = 1.0 else inShadow = 0.0 最终颜色 = (1 - inShadow) * litColor + inShadow * ambientColor
⚠️ Shadow Mapping 的两个 Pass
阴影映射需要渲染场景两次：Shadow Pass（从光源视角，只写深度）和 Lighting Pass（从相机视角，正常渲染 + 阴影测试）。这意味着场景的几何复杂度直接决定了阴影计算的开销。

7.2 PCF 软阴影 (Percentage Closer Filtering)

基础的阴影映射产生的是硬阴影——每个像素要么完全在阴影中，要么完全不在。但现实世界中，阴影的边缘通常是柔和渐变的（半影，penumbra），这是因为真实光源具有有限的面积。

PCF（Percentage Closer Filtering）是最常用的软阴影技术。它的做法是：对阴影贴图中采样点周围的多个 texel 进行深度比较，然后统计"有多少比例的采样点认为该片元在阴影中"，这个比例就是阴影的强度。

PCF 软阴影计算： shadow = 0 for each sample (x, y) in filterKernel: shadow += (fragDepth > shadowMapDepth(x, y)) ? 1.0 : 0.0 shadow /= totalSamples // shadow 值在 [0, 1] 之间，0 = 完全光照，1 = 完全阴影
关键特性：PCF 必须在深度比较之后做平均，而不是先平均深度再比较。如果先平均深度，你会得到错误的软阴影形状。这就是"Percentage Closer"名称的由来。
📚 知识扩展：更高品质的软阴影方案

除了 PCF，现代引擎还使用：

  • VSM（Variance Shadow Map）：存储深度和深度的平方，允许在像素着色器中做高斯模糊，然后通过切比雪夫不等式估计阴影概率。优点是可以预过滤，缺点是在多光源重叠时可能产生漏光（light leaking）。
  • CSM（Cascaded Shadow Map）：见 7.3 节，解决大场景阴影精度问题。
  • PCSS（Percentage Closer Soft Shadows）：根据遮挡物的距离动态调整 PCF 的采样核大小，模拟物理正确的半影宽度。

7.3 级联阴影映射 (CSM)

级联阴影映射（Cascaded Shadow Maps, CSM）用于解决一个关键问题：当相机的近裁剪面和远裁剪面距离差距很大时（比如从 1 米到 1000 米），一张阴影贴图的分辨率无法同时满足近处的精度和远处的覆盖范围。

CSM 的解决方案是将相机的视锥体（Frustum）沿深度方向分割成多个级联（Cascade）：

  1. 级联 0：覆盖最近区域（如 0-20 米），使用高分辨率阴影贴图
  2. 级联 1：覆盖中距离（如 20-80 米），中等分辨率
  3. 级联 2：覆盖远距离（如 80-500 米），较低分辨率

渲染时，每个片元找到自己所属的级联，使用对应的阴影贴图进行深度比较。通常使用 3-5 个级联就能获得很好的效果。

7.4 阴影质量优化

在使用阴影映射时，会遇到几种常见的视觉瑕疵：

Shadow Acne（阴影痤疮）

由于浮点精度限制，表面本身的片元深度可能与阴影贴图中的深度非常接近，导致"自阴影"——表面出现条纹状的伪影。解决方案：在深度比较时添加一个小的偏移量（depth bias），让比较稍微"宽松"一些。

Peter Panning（Peter 飘移）

如果 depth bias 设置得太大，物体底部的阴影会被切断，物体看起来像"飘浮"在地面上方。解决方案：使用法线偏移（Normal-based Bias），沿表面法线方向偏移而非只沿深度方向，或者使用 Slope-Scale Bias——根据表面与光线的夹角动态调整偏移量。

锯齿 (Aliasing)

阴影贴图分辨率不足时，阴影边缘出现锯齿。解决方案：使用 CSM 提高近处精度，使用 PCF 软化边缘，使用更高的阴影贴图分辨率。

7.5 体积光 (Volumetric/Raymarched Shadows)

体积光（Volumetric Lighting）让光看起来有"实体感"——你能看到光束穿过空气中的灰尘和雾气散射出来的光柱效果（也叫"上帝之光"或"丁达尔效应"）。

在实时渲染中，体积光通常通过光线步进（Ray Marching）实现：从相机向每个屏幕像素发射一条射线，沿着射线等间距采样，在每个采样点处计算光照的累积散射量。

体积光散射积分（简化）： L_volumetric = Integral[ T(s) * sigma_s * L_in(s) ds ] 其中 T(s) = exp(-Integral[ sigma_e(t) dt ]) 是透射率 sigma_s 是散射系数，sigma_e 是消光系数 实时近似：将积分离散化为 N 个采样步
性能注意事项：体积光的光线步进计算量很大（每个像素需要多次采样）。常见优化策略包括：降低分辨率渲染（半分辨率或 1/4 分辨率），减少步进次数，使用 temporal reprojection 复用上一帧的结果，以及在 G-Buffer 中做空间插值。

CHAPTER 8

第8章 光与颜色 (Light and Color)

"在我们实现基于物理的渲染之前，我们首先需要了解如何对光和颜色进行量化建模。并且在我们执行基于物理的渲染之后，我们还需要将最终结果转换为可以显示的数值，并考虑屏幕属性和观察环境对它的影响。"

-- RTR4, Chapter 8

本章建立了渲染中光与颜色的数学基础。如果说渲染管线是"硬件架构"，那么光与颜色的理论就是"编程语言"——没有它，我们无法正确地表达和计算光照。

8.1 光度学基础 (Radiometry)

在基于物理的渲染中，我们需要用严格的物理量来描述光的传播。核心的光度学量有：

物理量英文名称符号单位直觉理解
辐射通量 Radiant Flux / Power Φ 瓦特 (W) / 流明 (lm) 光源总共发出多少能量
辐射强度 Radiant Intensity I W/sr (瓦特每球面度) 单位立体角内发射多少能量
辐照度 Irradiance E W/m² 单位面积上接收多少能量（入射）
辐射亮度 Radiance L W/(sr·m²) 单位面积、单位立体角内的能量（最核心的量）
为什么 Radiance 是最重要的？因为在渲染方程中，所有入射和出射的光都用 Radiance 来表示。Radiance 描述了"从某个方向、某个点上，你能看到多少光"。相机传感器记录的就是 Radiance，BRDF 的输入输出也是 Radiance。
辐照度 E 与辐射亮度 L 的关系： E = Integral[ L(i) * cos(theta_i) dw ] 即：辐照度等于所有方向入射辐射亮度的余弦加权积分 其中 theta_i 是入射方向与表面法线的夹角

8.2 色彩空间 (Color Spaces)

色彩空间定义了如何用数字来表示颜色。在实时渲染中，最常见的色彩空间有：

RGB 色彩空间

最直观的颜色表示法。使用红、绿、蓝三个通道的值来描述颜色。但 RGB 有多种"口味"——不同的 RGB 色彩空间使用不同的原色（primary）和传递函数（transfer function），导致同样的 RGB 值在不同空间中显示不同颜色。

sRGB 色彩空间

是当今显示器和互联网内容的事实标准。sRGB 定义了标准的 RGB 原色、白点和Gamma 曲线（大约 gamma = 2.2）。几乎所有 JPEG/PNG 图片和网页颜色都使用 sRGB 编码。

线性空间 vs Gamma 空间

这是渲染中最容易混淆但至关重要的概念。线性空间（Linear Space）中，光的物理能量与数值成正比（值翻倍 = 能量翻倍）。Gamma 空间（sRGB 等）中，数值经过了非线性编码，值翻倍并不等于能量翻倍。

常见错误：如果在 Gamma 空间中做光照计算（如两个颜色的乘法），结果在物理上是不正确的。比如 50% 灰色 x 50% 灰色，在 Gamma 空间中得到 25%（看起来太暗），在线性空间中应该得到 50%。所有光照计算必须在线性空间中进行。

8.3 Gamma 校正

Gamma 校正是连接线性计算和 Gamma 显示的桥梁。完整的流程是：

  1. 输入纹理（通常为 sRGB）通过 sRGB -> Linear 转换来解码
  2. 在 Linear 空间中执行所有光照计算（加法、乘法、插值）
  3. 最终结果通过 Linear -> sRGB 转换来编码，输出到显示器
sRGB -> Linear (Gamma 解码): C_linear = C_srgb / 12.92 (当 C_srgb <= 0.04045) C_linear = ((C_srgb + 0.055) / 1.055)^2.4 (当 C_srgb > 0.04045) 简化近似: C_linear = C_srgb^2.2 Linear -> sRGB (Gamma 编码): C_srgb = 1.055 * C_linear^(1/2.4) - 0.055
💡 GPU 硬件自动处理 sRGB
现代 GPU 支持在纹理采样时自动进行 sRGB -> Linear 转换（设置纹理为 SRGB 格式），在写入 render target 时自动进行 Linear -> sRGB 转换（设置 render target 为 SRGB 格式）。你应该利用这些硬件功能，而不是在着色器中手动做 pow 运算。

8.4 HDR 与色调映射 (Tone Mapping)

HDR（High Dynamic Range，高动态范围）意味着渲染结果中的亮度值可以远超 [0, 1] 范围——太阳的亮度可能是白色纸面的数万倍。但显示器的亮度范围是有限的（LDR, Low Dynamic Range），因此需要一个从 HDR 到 LDR 的转换过程：色调映射（Tone Mapping）。

比喻：HDR -> LDR 就像"把交响乐录成 MP3"。交响乐现场的声音动态范围极大——从极弱的呢喃到极响的定音鼓。CD 和 MP3 的动态范围有限，录音师必须通过"压缩"来把巨大的音量差异塞进有限的范围。色调映射做的是类似的事——把巨大的亮度差异"压缩"到显示器能显示的范围内，同时尽量保留重要的视觉信息。

常见的色调映射算子：

  • Reinhard：C_out = C_in / (1 + C_in)，简单的除法映射，趋向于让所有亮度趋向 1.0
  • Filmic (ACES)：电影行业标准的 S 形曲线，保留高光和暗部细节，视觉效果自然
  • Uncharted 2 Filmic：John Hable 提出的色调映射，在游戏界非常流行

CHAPTER 9

第9章 基于物理的着色 (Physically Based Rendering)

"我们将从头开始建立起对基于物理的着色模型的理解。在本章节中，我们首先会从潜在的物理现象开始，介绍一系列包含各种渲染材质的着色模型，最后介绍这些材质的混合方法和过滤方法，从而避免材质出现瑕疵（aliasing）并保持表面外观。"

-- RTR4, Chapter 9

基于物理的渲染（PBR）是现代实时渲染的基石。与早期的"经验式"着色模型（如 Phong、Blinn-Phong）不同，PBR 从光的物理本质出发，确保渲染结果在物理上是合理的——无论光照条件如何变化，材质的外观都保持一致和可信。

比喻：传统着色 vs PBR 的区别。传统着色就像"用颜料画效果"——画师凭感觉调颜色，在特定光线下看起来不错，但换了光线就不对了。PBR 就像"用物理公式计算效果"——你描述的是材质的物理属性（金属还是非金属、光滑还是粗糙），然后物理公式确保在任何光线下都正确。

9.1 PBR vs 传统着色

对比维度传统着色（Phong/Blinn-Phong）PBR（Cook-Torrance）
物理基础 经验公式，人为设计 基于光的物理行为
能量守恒 不保证（可能反射出比入射更多的光） 严格遵守（反射 + 漫反射 <= 入射）
菲涅尔效应 通常不包含 内置，掠射角反射增强
参数一致性 不同光照下需要调整 任何光照下都物理合理
材质工作流 漫反射色 + 高光色 + 光泽度 Albedo + 金属度 + 粗糙度

9.2 光与物质相互作用的五种现象

当光照射到物体表面时，会发生以下五种物理现象：

  1. 反射（Reflection）：光从表面"弹开"，方向由表面法线决定。镜面反射（Specular）是光滑表面的反射，入射角等于反射角。
  2. 折射（Refraction）：光进入透明/半透明材质时改变方向，由斯涅尔定律（Snell's Law）描述。这是透明物体（玻璃、水）的核心光学行为。
  3. 散射（Scattering）：光在材质内部被微粒多次反射，最终从不同方向射出。漫反射（Diffuse）本质上是次表面散射在宏观尺度上的近似。
  4. 吸收（Absorption）：材质将光能转化为热能或其他形式。被吸收的光不再参与后续的光传输，决定了材质的颜色（未被吸收的光的颜色就是我们看到的颜色）。
  5. 透射（Transmission）：光穿过物体从另一侧射出。常见于玻璃、水、薄纸等材质。
核心洞察：物体的颜色来源于选择性吸收。白光包含所有波长，当照射到一个红色苹果上时，绿色和蓝色的光被吸收，只有红色光被散射回我们的眼睛。所以苹果"看起来是红的"并不意味着它发出红光，而是它"反射"了红光。

9.3 BRDF 定义与物理约束

BRDF（Bidirectional Reflectance Distribution Function，双向反射分布函数）是 PBR 的数学核心。它描述了：给定入射方向和出射方向，表面将多少入射光反射到出射方向。

BRDF 定义： f_r(l, v) = dL_o(v) / (dE_i(l)) 其中 l = 入射方向 (light), v = 出射方向 (view) L_o(v) = 出射辐射亮度, E_i(l) = 入射辐照度 BRDF 的单位是 1/sr (每球面度) 渲染方程（简化版）： L_o(v) = Integral[ f_r(l, v) * L_i(l) * cos(theta_l) dw ] 即：出射光 = 所有方向入射光的 BRDF 加权余弦积分

一个物理合理的 BRDF 必须满足两个约束：

  1. Helmholtz 互易性（Reciprocity）：f_r(l, v) = f_r(v, l)。交换入射和出射方向，BRDF 值不变。这意味着光路可逆——光从 A 到 B 和从 B 到 A 的反射行为相同。
  2. 能量守恒（Energy Conservation）：反射的总能量不超过入射能量。对于完美镜面（全部反射），反射率 = 1；对于粗糙表面，漫反射分量和镜面反射分量之和不能超过入射能量。

9.4 Cook-Torrance 镜面反射 BRDF

Cook-Torrance BRDF是实时渲染中最广泛使用的镜面反射模型，也是 PBR 材质的数学核心：

Cook-Torrance 镜面 BRDF： f_specular(l, v) = D(h) * F(v, h) * G(l, v, h) / (4 * (n . l) * (n . v)) 其中： h = normalize(l + v) -- 半程向量 (half vector) D(h) = 法线分布函数 (Normal Distribution Function) F(v, h) = 菲涅尔函数 (Fresnel Function) G(l, v, h) = 几何遮蔽函数 (Geometry Function) (n . l) = 法线与入射方向的点积（余弦值） (n . v) = 法线与出射方向的点积（余弦值）

完整的 PBR 着色公式结合了漫反射和镜面反射分量：

完整 PBR 反射方程： f_r(l, v) = k_d * f_lambert + k_s * f_cook-torrance f_lambert = albedo / PI k_d + k_s = 1 (能量守恒) k_s = F(v, h) (菲涅尔决定了镜面反射的比例) k_d = (1 - k_s) * (1 - metallic) (金属没有漫反射)

9.5 法线分布函数 (NDF)：GGX/Trowbridge-Reitz

法线分布函数 D(h)描述了表面微法线（microfacet normal）等于半程向量 h 的概率密度。它决定了高光的形状和集中程度。

GGX/Trowbridge-Reitz NDF： D(h) = alpha² / (PI * ((n . h)² * (alpha² - 1) + 1)²) 其中 alpha = roughness² roughness 越大 -> alpha 越大 -> 高光越分散越暗淡 roughness 越小 -> alpha 越小 -> 高光越集中越明亮
直觉理解：GGX 有一个"长尾巴"特性——即使是高粗糙度值，在镜面反射方向的远处仍有微弱的高光。这与真实世界中光泽表面（如有光泽的塑料、有涂层的木材）的观察结果一致，也是 GGX 被广泛采用的原因之一。

9.6 菲涅尔效应 (Fresnel Effect)

菲涅尔效应描述了反射率随观察角度变化的现象：当你从几乎平行于表面的方向（掠射角）看过去时，所有材质的反射率都会趋向于 100%。这就是为什么水面在远处看起来比近处更反射——你看到的水面更接近掠射角。

Schlick 近似（实时渲染中最常用的菲涅尔近似）： F(v, h) = F0 + (1 - F0) * (1 - (v . h))^5 F0 = 正入射时的反射率 对于非金属（电介质）：F0 约为 0.02-0.05 对于金属（导体）：F0 约为 0.5-1.0（即 F0 = albedo 色值） (v . h) = 出射方向与半程向量的点积
📚 知识扩展：电介质 vs 导体

材质按导电性分为两类，它们的菲涅尔行为截然不同：

  • 电介质（Dielectrics / 绝缘体）：如塑料、木材、石材、皮肤、水。F0 值很低（约 0.02-0.05），且在可见光范围内几乎不随波长变化，所以高光几乎都是白色/灰色。
  • 导体（Conductors / 金属）：如金、银、铜、铁。F0 值很高（约 0.5-1.0），且随波长变化，所以金属的高光带有颜色（金的高光是黄色偏暖，铜的高光是红色偏暖）。

这个区别是 PBR 金属度-粗糙度工作流的核心基础。

9.7 几何遮蔽函数 (Geometry Function)：Smith G

几何遮蔽函数 G(l, v, h)描述了微表面（microfacets）之间互相遮挡的概率。当表面粗糙时，一些微面的"碗"可能会挡住光线或视线，使得实际参与反射的能量减少。

Smith-GGX 几何函数： G1(v) = (n . v) / ((n . v) * (1 - k) + k) 分离形式 G_Smith(l,v) = G1(l) · G1(v)
Karis 重映射（UE4，实时直接光照）：k = (roughness + 1)² / 8
IBL 预过滤：k = roughness² / 2

RTR4 提醒：实践中最广为采用的是 Heitz 推荐的高度相关Smith 形式（G2(l,v,h) 同时考虑 l、v 的相关性）；上述"两式简单相乘"的可分离假设会导致 BRDF 过暗。

9.8 金属度-粗糙度工作流 (Metalness-Roughness Workflow)

现代游戏引擎（Unity、Unreal Engine、Godot）统一使用金属度-粗糙度工作流来定义材质。这个工作流只需要三个核心纹理贴图：

  • Albedo 贴图：表面的基础颜色。对于金属，albedo 就是其反射颜色（F0）；对于非金属，albedo 是漫反射颜色，不含任何光照/阴影/高光信息。
  • 金属度贴图（Metalness Map）：0 = 非金属（电介质），1 = 金属。通常灰度图，中间值用于表示混合材质（如生锈的金属：铁锈处 = 0，金属处 = 1）。
  • 粗糙度贴图（Roughness Map）：0 = 完美光滑（如镜面），1 = 完全粗糙（如粗布）。控制高光的扩散程度。
制作 Albedo 贴图的原则：Albedo 中不能包含：阴影、高光、环境反射、AO 信息。这些都应该由引擎在运行时根据光照条件实时计算。如果 Albedo 中混入了光照信息，会导致 PBR 计算结果"双重光照"——看起来过曝或颜色不正确。

9.9 基于图像的光照 (IBL)

IBL（Image-Based Lighting）使用环境贴图（如 HDR 环境全景图）来提供来自所有方向的环境光照。它分为两个部分：

  1. 辐照度贴图（Irradiance Map）：用于漫反射分量的环境光照。通过对环境贴图做低频卷积/模糊得到，代表了每个方向上环境光的平均入射辐照度。
  2. 预过滤环境贴图（Prefiltered Environment Map）：用于镜面反射分量。将环境贴图按粗糙度级别做不同程度的模糊——粗糙度越大，高光越分散，对应的环境贴图越模糊。
  3. BRDF 积分贴图（BRDF LUT）：一个 2D 查找纹理，预计算了 BRDF 的积分结果（菲涅尔和遮蔽项的乘积），避免在运行时做昂贵的积分运算。
IBL 镜面反射近似： L_specular = PrefilteredColor(Roughness, R) * (F0 * BRDF_LUT.x + BRDF_LUT.y) 其中 R = reflect(-v, n) 是反射方向 BRDF_LUT.x 对应缩放的菲涅尔项 BRDF_LUT.y 对应缩放的几何遮蔽项

CHAPTER 10

第10章 局部光照 (Local Illumination)

"本章节研究了刻画（portray）复杂光源的算法。我们在进行表面着色的时候，需要考虑到这些光线是从某些物理对象中发射出来的，这些物体具有独特的形状。"

-- RTR4, Chapter 10

局部光照（Local Illumination）考虑的是光源直接照射到表面产生的光照效果，不考虑光线在场景中的多次弹射。虽然名字叫"局部"，但局部光照是实时渲染中最重要的光照组成部分——大多数场景的视觉质量主要取决于直接光照的质量。

比喻：局部光照 vs 全局光照。局部光照就像你在房间里打开一盏台灯——你只关心台灯直接照到桌面的效果。全局光照则还要考虑光线从桌面反射到墙壁、再从墙壁反射到天花板......的多次弹射效果。局部光照计算简单快速，全局光照真实但昂贵。

10.1 环境光 (Ambient Light)

环境光是最简单的光照模型——为场景中的所有表面添加一个均匀的、无方向性的光照。它模拟的是光线在场景中多次弹射后产生的"填充光"（fill light）。

环境光着色： color = ambientColor * albedo 通常 ambientColor 是一个低强度的常量（如 (0.1, 0.1, 0.1)） 这是最低保底的光照——即使是阴影中也不会完全黑暗
局限性：均匀的环境光是非常粗略的近似。真实场景中，不同位置的环境光强度是不同的（角落更暗，开阔处更亮）。更高级的方法如 SSAO、光探针（Light Probes）可以提供空间变化的环境光。

10.2 方向光 (Directional Light)

方向光模拟远距离光源（如太阳），所有光线平行射入。它没有位置属性，只有方向。

方向光漫反射（Lambert）： diffuse = max(dot(n, l), 0) * lightColor * albedo 其中 n = 表面法线，l = 光照方向（从表面指向光源） dot(n, l) = cos(theta)，theta 是法线和光方向的夹角 max(..., 0) 确保背面不受光

10.3 点光源 (Point Light) 与衰减

点光源从一个点向所有方向发射光线，强度随距离衰减。在物理上，点光源的照度遵循平方反比定律（Inverse Square Law）：

点光源衰减公式： E = Intensity / (d² + 1) 其中 d = 表面到光源的距离 分母中的 +1 是为了防止 d=0 时除以零 物理精确版本：E = Intensity / d² 但在游戏中通常会添加线性项来避免远处衰减过快： E = Intensity / (1 + k_c*d + k_l*d² + k_q*d³) (衰减三参数模型)
实践建议：物理精确的 1/d² 衰减在游戏场景中可能导致"光看起来不够远"的问题。游戏引擎通常使用额外的线性项来让衰减更柔和：E = Intensity / (d² + d + 1)。Three.js 的 PointLight 默认使用这种修正模型。

10.4 聚光灯 (Spot Light)

聚光灯发射锥形光束，需要额外的参数来定义光锥的范围和边缘的柔和程度：

  • 内锥角（Inner Angle）：完全照亮的锥形区域
  • 外锥角（Outer Angle）：光照从完全亮度衰减到零的区域
  • 衰减（Falloff）：在内锥角和外锥角之间，光照强度平滑过渡
聚光灯因子： spotEffect = smoothstep(outerCos, innerCos, dot(lightDir, spotDir)) finalIntensity = attenuation * spotEffect * lightColor * max(dot(n, l), 0)

10.5 区域光 (Area Light)

区域光是有物理面积的发光体（如荧光灯管、发光面板、窗户透过的光）。区域光的特点是产生软阴影和柔和高光——因为光源上的每个点都在不同的方向发光。

实时渲染中的近似：精确的区域光计算需要对光源面积上的每个点做积分，计算量很大。常见的实时近似方法包括：
1. LTC（Linearly Transformed Cosines）：将区域光的积分转化为可以实时计算的近似公式
2. 球面光源近似（Spherical Area Light）：将区域光近似为球面光源
3. 多采样：在光源表面上取若干采样点，每个点作为点光源来计算，然后平均

10.6 多光源累加

在实时场景中，通常会同时有多个光源。每个光源的贡献通过加法累加：

最终颜色 = ambient + sum(light_i_contribution for each light_i) 其中每个光源的贡献： light_i_contribution = attenuation_i * (diffuse_i + specular_i) 注意：颜色值可以超过 1.0（HDR），需要后续的色调映射来处理
性能警告：每增加一个光源，着色器就要多执行一次光照计算。场景中光源数量直接决定了片段着色器的执行时间。常见优化策略包括：使用 light culling（前向渲染中只计算影响当前像素的光源）、延迟着色（Deferred Shading）和 light clusters。

CHAPTER 11

第11章 全局光照 (Global Illumination)

"本章节研究了模拟光线和场景多次相交的算法，这可以大大增强图像的真实感。我们还会研究环境光遮蔽（ambient occlusion）和定向遮蔽（directional occlusion），介绍在漫反射表面和镜面表面上渲染全局光照效果的方法，以及一些很有前景的统一方法。"

-- RTR4, Chapter 11

全局光照（GI）考虑光线在场景中的多次弹射（bounce），模拟间接光照效果。它是区分"游戏画质"和"电影画质"的关键因素之一。没有 GI，阴影中是纯黑的、角落是死暗的——有了 GI，光会从地面反射到天花板、从红色墙壁反射到白色地板上产生"颜色渗透"。

比喻：直接光照只看"第一印象"，全局光照追踪"连锁反应"。想象一个阳光房：太阳光直接照进来是直接光照。但阳光照到黄色窗帘后，一部分光被反射到白色墙壁上，墙壁因此带上了一层淡淡的黄色——这就是全局光照（间接光照）。没有全局光照，墙壁上永远看不到窗帘的颜色渗透。

11.1 环境光遮蔽 (AO / SSAO / HBAO)

环境光遮蔽（Ambient Occlusion, AO）是一种近似全局光照的技术，专门处理"角落和缝隙处应该更暗"这一现象。它不需要做完整的光线弹射计算，只需要检测表面周围的几何遮挡程度。

SSAO（Screen Space Ambient Occlusion）

由 Crytek 在 2007 年的 Crysis 中首次引入。SSAO 在屏幕空间中工作：对于每个像素，在深度缓冲中采样周围多个点，判断哪些点比当前像素更接近相机（即被遮挡），遮挡比例越高，环境光越暗。

SSAO 的工作原理：
  1. 读取当前像素的深度值，重建其在 3D 空间中的位置
  2. 在该位置周围的半球体内随机采样若干点
  3. 将采样点投影到屏幕空间，比较其深度与深度缓冲中的值
  4. 如果深度缓冲中的值更小（更近），说明有遮挡物
  5. 统计遮挡比例，作为环境光的衰减因子

HBAO（Horizon-Based Ambient Occlusion）

HBAO 是 SSAO 的改进版。它不是随机采样，而是沿多个方向追踪地平线角度。对于每个方向，找到第一个遮挡采样点的角度（"地平线"），然后用这个角度来计算遮蔽强度。HBAO 比 SSAO 质量更高，但计算量也更大。

GTAO（Ground Truth Ambient Occlusion）

由 NVIDIA 提出的更现代的 AO 方法，在质量和性能之间取得了很好的平衡。它使用与 HBAO 类似的地平线角度追踪方法，但采样策略更优化。

11.2 屏幕空间反射 (SSR)

屏幕空间反射（Screen-Screen Reflection, SSR）在屏幕空间中计算反射效果——对于每个像素，沿反射方向在屏幕空间中"步进"（Ray Marching），找到反射到的位置并采样颜色。

SSR 的基本流程：
  1. 对于每个屏幕像素，计算其表面法线和反射方向 R = reflect(viewDir, normal)
  2. 沿 R 方向在屏幕空间中进行光线步进（Ray Marching）
  3. 在每一步，将当前位置投影到屏幕空间，检查深度缓冲
  4. 当步进深度与深度缓冲匹配时，采样该位置的颜色作为反射颜色
SSR 的局限性：SSR 只能反射屏幕空间中可见的内容。如果反射方向指向屏幕外（如物体背面的反射），SSR 无法处理——这时候只能回退到环境贴图反射。此外，SSR 在反射边缘处容易出现瑕疵，需要做边缘淡化（fade）处理。

11.3 光线传播体积 (Light Propagation Volumes)

光线传播体积（LPV）由 Crytek 提出（首次用于 Crysis 3），是一种在 3D 体积网格中传播间接光照的实时 GI 技术。其核心思想是：

  1. 注入（Injection）：从直接光照中提取每个表面上方的间接光照方向和强度，注入到最近的体积网格单元中
  2. 传播（Propagation）：在 3D 网格中，每个单元将其光照信息"扩散"到相邻的 6 个单元（上下左右前后），迭代多轮以模拟光的弹射
  3. 采样（Sampling）：在渲染时，每个表面采样其所在位置的体积网格数据来获取间接光照
LPV 的特点：LPV 的优势是能够实时计算单次弹射的间接光照，且不依赖于屏幕空间。缺点是分辨率受限于体积网格的密度（过低的分辨率会产生明显的"光晕"伪影），且多次弹射的计算开销较大。

11.4 屏幕空间全局光照 (SSGI)

屏幕空间全局光照（SSGI）是近年来游戏引擎中非常流行的技术，它将 SSAO 扩展为不仅计算遮蔽，还计算间接光照的颜色和强度。

SSGI 的工作原理与 SSAO 类似，但关键区别在于：不仅统计遮挡比例，还采样遮挡物的颜色，计算遮挡物反射过来的间接光照颜色。这样就能实现颜色渗透（color bleeding）等效果。

11.5 前向渲染 vs 延迟渲染

全局光照和复杂光照的计算效率与渲染架构密切相关。两大主流渲染架构是前向渲染（Forward Rendering）和延迟渲染（Deferred Shading）。

前向渲染 (Forward Rendering)

对每个物体，直接运行片段着色器计算所有光照。如果场景中有 N 个物体和 M 个光源，则需要 N * M 次光照计算。优势：支持透明物体、节省显存（不需要 G-Buffer）。劣势：多光源场景下性能瓶颈明显。

延迟渲染 (Deferred Shading)

分两步进行：第一步（Geometry Pass）渲染所有不透明物体到 G-Buffer（Geometry Buffer），记录每个像素的位置、法线、Albedo、粗糙度等信息。第二步（Lighting Pass）对每个光源，使用 G-Buffer 数据计算该光源对全屏像素的贡献。优势：光照计算与场景复杂度无关。劣势：不支持 MSAA、需要大量显存带宽、不支持透明物体。

混合架构：现代引擎通常使用混合方案：延迟渲染处理不透明物体的复杂光照，前向渲染处理透明物体和粒子特效。这种架构兼具两者的优势。
